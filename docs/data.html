Data

Everything behind this site, in two formats. Both are generated by the same pipeline that writes the pages, from the same validated tables, so the website and the downloads cannot disagree. Free to reuse with attribution.

Downloads

Three conventions to know before you open these. Join on dbn and never on a school name. An empty value is never a zero: the status column says whether the source reported it, withheld it for a small group, or published nothing. Percentages are proportions between 0 and 1 unless the data dictionary says otherwise.

The workbook's historical sheet carries a headline set of measures across every year, because the full observation table is over 1.6 million rows and Excel stops at about one million. The CSV archive carries everything.

Sources and freshness

Every period below is read from inside the data, not from the date a file was published. Several New York City open data pages report a recent update when only the description changed.

Data dictionary

Every measure on the site, its unit, and which schools publish it. The identifier is the value in the metric_id column of the downloads.

Using the JSON directly

The site is static, so the files its own pages read are a usable interface. No key, no rate limit, and CORS is open because GitHub Pages serves it that way. Paths are stable; treat a change to them as a breaking change. 

data/search-index.json      every school: DBN, name, borough, district, type, grades, status
data/metrics.json           every measure: label, unit, category, which schools report it
data/sources.json           every source with its period, coverage and limits
data/status.json            build date, reporting periods, counts, display constants
data/schools/{DBN}.json     one school: identity, every series, every program

A school file holds series keyed by measure identifier. Each series has parallel arrays: y for school years, v for values, and optionally n for group sizes, c for the comparison group average, s for the City's score, b for its band, bd for a published bound such as "Above 95%", st for status where anything is not a plain reported value, and rt for the report type where a school files two.

An absent st array means every value in that series was reported. A null in v is never a zero.

Rebuilding it yourself

The pipeline is four Python stages and an entry point:

python -m venv .venv
.venv/bin/pip install pandas requests openpyxl XlsxWriter
.venv/bin/python run.py

The first run downloads about 230 MB and geocodes the school addresses, which takes roughly fifteen minutes. Later runs reuse both caches. Every threshold, source identifier and display rule lives in pipeline/00_config.py, so you can change an assumption and rebuild the whole site against it.
